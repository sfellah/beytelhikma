## 2. Corrigé

### Défauts de comportement

| Où | Ce qui n'allait pas | Tenu par |

| `src/renderer/js/router.js` | `resolve()` est `async` et réentrant : deux navigations rapprochées laissaient la première vue **jamais démontée**. ### Ce qui a été retiré

- **L'entrée « traduire » du menu de sélection du lecteur** : elle n'ouvrait
  qu'un message d'attente. Ses deux clés de catalogue partent avec.
- **Huit clés de catalogue orphelines** (`reader.font.*`, `settings.font.*`,
  `settings.appearance*`, `settings.fontFamily`) — restes d'avant
  `shared/fonts.js`.
- **Quatre fonctions mortes** : `FACETS`, `sectionBlock`, `pageLabel`,
  `currentRoute`.
- **Neuf blocs CSS morts** : `.skeleton` et son `@keyframes`, `.layer__people`,
  `.person-chip*`, `.detail__actions-row`, `.settings__stack`,
  `.settings__preview`, `.segmented__text`.
- **Huit icônes jamais citées** : `logout`, `bell`, `user`, `arrowUpRight`,
  `more`, `moreVertical`, `share`, `folder`.

### Contrôles ajoutés

- **`test/i18n.test.js`** — aucune clé de catalogue orpheline. Les deux familles
  bâties à l'exécution sont exemptées, mais l'exemption est **adossée à son
  gabarit** : le test vérifie que le fichier qui la bâtit contient encore le
  littéral.
- **`test/router.test.js`** — aucune vue ne survit à son remplacement.
- **`apps/mobile/scripts/verify.mjs`** — les deux applications posent le même
  `user_version`. Le numéro est écrit en dur des deux côtés, faute d'un module
  partageable ; deux clients sur une même racine se marcheraient dessus.

### Documentation remise d'aplomb

`README.md` annonçait encore trois findings de sécurité **déjà corrigés** ;
`apps/desktop/README.md` affirmait que les polices venaient de Google Fonts
(elles sont embarquées depuis), que le lecteur portait ses propres ambiances
(c'est le thème de l'application), que `SHORTCUTS` vivait dans `views/reader.js`
(c'est `components/shortcuts.js`), et que `catalog-updater` tournait au démarrage
(rien ne l'appelle).

## 3. Laissé de côté, volontairement

| Sujet | Pourquoi on n'y touche pas |
| --- | --- |
| ~~**Câbler `checkCatalogUpdate` au démarrage**~~ — **fait le 2026-08-02**, après cet audit | La décision d'interface a été prise : une bande écartable, 2,5 s après le premier rendu, cinq branches sur six silencieuses, et l'écarter refuse cette version-là. `declineCatalogUpdate` a enfin un appelant. |
| **`#materialize` réécrase le catalogue téléchargé** par la bibliothèque source si celle-ci est plus récente | Ne concerne que le développement — une application empaquetée n'a pas de source. Le « corriger » casserait le va-et-vient entre `dist/shamela` et le bucket, qui est le mode de travail courant. |
| **FTS5 sur Android contre `LIKE` sur le bureau** | Les deux ne rendent pas les mêmes résultats (`نحو` : 7 contre 94). Aligner est un arbitrage produit, pas une correction. |
| **`searchLibrary` et `searchInBook` ne comptent pas pareil** | Même raison : un livre annoncé à 38 occurrences peut n'en montrer que 13. Il faut choisir laquelle des deux fait foi. |
| **`publish_minio.py` écrit `object_key` avant l'envoi** | Relu : le nettoyage de `release_library.py` n'a lieu qu'après une publication **et** une vérification anonyme réussies, et un échec laisse les fichiers en place, donc le passage suivant renvoie. Ce n'est pas le défaut qu'on croyait. |
| **`getAnnotations` compte les onglets sans le filtre texte** | C'est écrit ainsi exprès : l'onglet qu'on ne regarde pas annoncerait toujours zéro. |
| **Version `1.0` du mobile alignée sur `0.3.1`** | Fait — mais aucune chaîne de publication Android n'existe ; le numéro ne veut encore rien dire. |

## 4. Deux dossiers vides qui résistent

`spikes/expo-reader/` et `spikes/capacitor-reader/` sont **vides** et n'existent
plus pour git — mais Windows refuse de les supprimer (« Device or resource
busy »), un processus tenant encore le dossier parent. Rien n'en dépend ; un
`rmdir` après avoir fermé Android Studio, Gradle ou un terminal ouvert là suffit.
